## 1. 阶段定位

第一、二批已经完成门类覆盖和基础图谱收束。第三阶段不继续批量增加门类名称，而是在既有门类中纵向增加独立、完整、可核验的临床证据路径，并同步维护已有来源。

第一波聚焦：

- 化学与化学工程；
- 纳米科学；
- 再生医学与组织工程；
- 合成生物学。

选题不针对脑卒中、肿瘤或其他疾病类型设置增减配额、比例目标或默认优先级。候选按证据可核验性、临床问题清晰度、图谱结构价值和内容可解释性评估。

## 2. 阶段目标

### 第一波目标

- 四个优先门类各新增至少一条独立临床路径；
- 形成 4 个可独立验收的证据包；
- 新增约 12—20 张 `source-checked` 证据卡；
- 每条路径贯通“门类 → 核心能力 → 技术 → 临床问题/疾病与健康状态 → 研究证据 → 患者结局”；
- 不创建只有名称、没有来源或没有临床关系的空节点。

### 完整阶段目标

- 累计新增约 8—12 条独立临床路径；
- 累计新增约 30—50 张高质量证据卡；
- 对受影响的既有来源完成风险和时效复核；
- 所有公开内容通过 R1 来源核验、自动数据验证和产品构建验证。

数量是工作包规划范围，不是为了凑数的硬指标；如果可靠来源不足，应缩小批次并记录延期原因，不降低核验标准。

## 3. 不纳入本阶段的事项

- 不设置独立医学专家审校流程。项目不具备该能力，专家审校不是发布关卡、增强路线或未来待办；页面继续透明披露“未经独立医学专家审核”。
- 不接通用户需求系统，不创建或连接 Cloudflare D1，不配置 Pages Binding，不建设审核后台。
- 不因本阶段扩张直接迁移到图数据库、语义检索服务或付费 AI 服务。
- 不以脑卒中、肿瘤或其他疾病类型的占比作为选题或验收要求。

## 4. 扩张流程

1. **路径蓝图**：为每个候选确定门类、核心能力、技术、临床问题、疾病或健康状态和患者结局。
2. **关系问题**：把“技术是否有效”拆成适用人群、比较对象、研究终点、安全性、监管范围和外推边界等可核验问题。
3. **候选发现**：扩展监管文件、指南、原始研究、系统综述和长期随访候选池；自动发现只用于排序，不决定纳入。
4. **逐条核验**：核对来源身份、可访问内容、研究设计、对象、终点、结果、阴性发现、利益冲突和限制。
5. **证据提取**：创建证据卡和必要的研究节点，事实、推断与项目分析分开保存。
6. **图谱策展**：优先复用现有节点；新增节点必须具有稳定 ID、别名、主导航归属和来源。
7. **双层写作**：分别编写通俗医学连接和具有新增信息的专业说明，避免重复。
8. **批次验收**：运行数据校验、覆盖审计、专业层去重、TypeScript 检查和完整构建，并完成人工页面抽查。
9. **冻结与发布**：保存蓝图、检索日志、来源清单、核验记录、验证报告和 Git 快照；对外推送或发布仍需用户确认。

## 5. 单个证据包完成标准

- 至少一条完整的能力—技术—临床问题—疾病/健康状态—证据路径；
- 具体疗效或风险结论由监管文件、指南或原始研究支持，定义级资料不代替临床证据；
- 证据卡包含研究对象、比较、终点、结果、限制、来源和最近核验日期；
- 监管批准、临床试验、早期人体、动物/体外和理论研究明确分层；
- 阴性结果、安全性、样本量、利益冲突和外推限制不被省略；
- `review_status: source-checked`、`publication_status: public`、`curation_method` 已明确；
- `expert_review_status: not-performed` 仅作为透明披露，不形成待审任务；
- `npm run validate:data`、`npm run audit:coverage`、`npm run audit:professional`、`npx tsc --noEmit` 和 `npm run build` 全部通过。
