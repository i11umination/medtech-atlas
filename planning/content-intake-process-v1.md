# 大型内容库内容扩展与入库流程 v1.1（R1）

状态：R1 已确认，取代“专家审核后方可公开”的旧门槛
确定日期：2026-09-13

## 1. 流程目标

将候选学术资料转化为来源可追溯、状态透明、可回滚的知识图谱内容。流程允许机器辅助发现、提取和整理，但公开前必须完成逐条来源核对、事实边界检查和自动验证。独立医学专家审核不是发布前提；除非另有记录，页面必须明确披露“未经独立医学专家审核”。

## 2. 内容生命周期

```text
候选发现
  → 元数据核验
  → 内容/全文可访问核验
  → 证据事实提取
  → 节点与关系策展
  → 通俗解释/未来方向
  → 自动数据验证
  → 来源与表述复核
  → 产品与构建验证
  → 带透明披露的公开快照
```

状态含义：

- `discovered`：只记录候选，不作为证据使用；
- `metadata-verified`：题名、作者、年份、DOI/注册号等已核对；
- `content-reviewed`：在合法可访问范围内完成摘要或全文级事实提取；
- `source-checked`：来源身份、可访问内容、提取事实、适用范围和关键限制已经逐条核对，可进入公开快照；
- `revise`：退回补充或改写；
- `blocked`：来源撤稿、不可核验或存在医学风险，不得进入发布候选；

证据卡另设三个互不替代的透明字段：

- `expert_review_status`：`not-performed` 或 `completed`；只陈述是否存在独立专家复核记录，不决定能否公开；
- `publication_status`：`hidden` 或 `public`；`public` 必须同时达到 `source-checked`；
- `curation_method`：`machine-assisted` 或 `human-curated`，说明内容如何整理。

## 3. 批次工作包

每个批次应具备以下记录：

1. 蓝图：门类、能力、技术、医学问题和证据目标；
2. 检索日志：平台、检索词、日期、筛选范围和下一步；
3. 来源清单：来源类型、访问状态、唯一标识和排除理由；
4. 证据卡：研究设计、对象、终点、结果、限制和研究阶段；
5. 图谱变更：新增/复用节点、关系、导航和 ID；
6. 内容稿：实体简介、证据通俗解释和未来方向；
7. 核验记录：来源访问层级、事实核对项、问题、处理意见、日期和状态；如有专家复核，再单独追加专家记录；
8. 验证报告：Schema、引用、导航、措辞和构建结果。

## 4. 各阶段输入、输出与关卡

### A. 蓝图确认

输入：已批准的本体、现有节点和临床主题。  
输出：`planning/first-batch-expansion-blueprint.md` 及明确的关系问题。  
关卡：未形成至少一条完整路径的门类只能保持规划状态。

### B. 来源发现与筛选

输入：关系问题、关键词矩阵和目标研究阶段。  
输出：`research/source-candidates.md`、`research/search-log.md` 的批次记录。  
关卡：B 路线用于扩大候选发现；A 路线负责最终纳入。撤稿或无法合法核验的来源必须排除。

### C. 证据提取

输入：已通过来源初筛的记录。  
输出：`data/evidence-index.json`、`evidence/EVD-*.md`、必要时的 `RES-*` 节点。  
关卡：没有研究设计、主要终点、限制或适用范围的来源不得支撑正式关系。

### D. 图谱策展

输入：结构化证据事实。  
输出：`data/nodes.json`、`data/relations.json`、`data/navigation-groups.json` 及必要的 `CAP-*` 节点。  
关卡：先复用已有实体；新实体必须有标准名、别名、主导航归属和可追溯来源。

### E. 内容编辑

输入：已策展的事实和关系。  
输出：实体简介、证据卡通俗解释、未来方向和来源核验备注。  
关卡：事实、推断和项目分析分开；不得删去阴性结果、样本量或关键局限。

### F. 自动验证

运行：`npm run validate:data`。  
关卡：Schema、ID、跨文件引用、Markdown、导航归属、阻断来源和高风险措辞全部通过。

### G. 来源与表述复核

输入：验证通过的批次工作包。  
输出：来源核验记录、逐条状态和公开披露字段。
关卡：逐条确认来源确实支持表述，研究阶段、对象、终点、阴性结果和限制没有被改写或省略。无法完成来源核验的内容进入 `revise` 或 `blocked`。独立医学专家复核为可选增强项，不阻塞 R1 发布。

### H. 产品与构建验证

运行：`npm run check`、`npm run build`，并完成页面、导航、搜索和移动端抽查。  
关卡：页面路径、状态徽标、证据链和医学免责声明均正确。

## 5. B 路线的使用边界

B 路线可以用于：

- 批量发现题名、作者、年份、DOI、注册号和摘要入口；
- 发现相近术语、别名、重复来源和潜在冲突来源；
- 为人工检索建立候选排序。

B 路线不能单独决定：

- 是否纳入医学证据；
- 研究阶段和监管状态；
- 疗效、安全性或患者适用范围；
- 是否达到 `source-checked` 或进入公开页面；自动发现不能自行作出这些决定，必须完成逐条来源对照。

## 6. 第一批执行顺序

1. 审核并定稿第一批五门类蓝图；
2. 确认核心能力节点命名和复用规则；
3. 用 B 路线扩展候选来源池；
4. 用 A 路线核验关键来源并建立证据卡；
5. 先完成每门类两条完整路径的最小骨架；
6. 运行自动验证器并修复全部阻断项；
7. 完成逐条来源与表述复核，写入透明披露字段；
8. 通过产品验证后形成批次公开快照；若以后获得专家资源，可追加可选复核记录。

## 7. 批次完成标准

- 五个科学门类均有明确范围和至少两个核心能力/技术连接；
- 每个门类至少两条完整路径，或明确记录延期原因；
- 约 30—50 张证据卡达到 `source-checked`；
- 所有公开候选关系均有来源、研究阶段、限制和最近核验日期；
- 自动数据验证、来源与表述复核、产品构建验证均通过；
- `blocked`、`revise`、`draft` 内容与公开证据卡严格分离；
- 每张公开证据卡均标明整理方式、专家复核状态，并展示非诊疗建议声明；
- 批次报告、检索日志和本地 Git 快照均已保存。
